# ANIMALT-Δ

TEXTALT / PALETALT / GLYPHALT の合成。
GIF・画像・動画を「背景色＋文字色の組み合わせ」で描いたカラー AA に変換し、
アニメーションのまま GIF で書き出す。

```
SOURCE ──┬─→ PALETTE ─┐
         │            ├─→ MATCH ─→ RENDER / EXPORT
FONT ────┴─→ GLYPHS ──┘
```

## パイプライン

| # | 由来 | 中身 | 実装 |
|---|---|---|---|
| 1 | TEXTALT | ビットマップシート（8x8 / 8x11 COOL / 8x11 POP）から1セルずつ切り出して 0/1 マスク化。1フォントに複数の Unicode ページ | `js/glyphs.js` |
| 2 | PALETALT | 全フレームをまとめて1つのヒストグラムにし、最大16色を抽出 | `js/palette.js` `js/quantize.js` |
| 3 | GLYPHALT | セルごとに (背景色, 文字色, グリフ) の最適な組を探す | `js/matcher.js` |
| 4 | 新規 | フレームを Worker に分散、GIF89a で書き出し | `js/convert.js` `js/worker.js` `js/gif.js` |

UI は左右2枚の展開式パネル（GLYPHALT-16 と同じ被せ方式）。
開閉は画面の左右端に貼り付いた縦タブ（`.edge-tab`）で行う。
タブはパネルより手前（z-index 22 対 20）にあるので、開いていてもそのまま押して閉じられる。
パネル側はタブのある辺に 38px の padding を入れて、中身がタブの下に潜らないようにしてある。
中央を押し縮めないので、パネルを開閉しても出力の見え方が動かない。
画面幅が 1100px 未満のときだけ、開いた側を残して反対側を閉じる。

数値スライダーには必ず数値入力を並べてある（`linkSlider`）。
どちらを触っても相手に反映し、変更通知は1本にまとめる。
数値入力は打ち途中（空文字や `-` だけ）を弾いてから同期し、
範囲外の値はフォーカスが外れた時点で丸める。
IMAGE ADJUST には、そのセクションだけを初期値へ戻す RESET を置いた
（初期値は `ADJUST_DEFAULTS` の1箇所にまとめてあるので HTML とずれない）。
コードは `view.js`（DOM と描画）/ `pipeline.js`（計算と依存関係）/
`controls.js`（配線）/ `main.js`（起動）に分けてある。
以前は main.js に全部入っていて 560行あった。

## 設計上の判断

**フォントは TTF/OTF ではなくビットマップシートから切り出す。**
ラスタライザ任せだと、字がセルのどこに乗るか（ベースライン・送り幅・
ヒンティング）を握れない。ドット絵は1px ずれれば別物になるので、
打った通りの点をそのまま使えるほうがいい。実際 8x11 の COOL と POP は
セル内で字の乗る高さが違う（COOL は上2行、POP は下2行が空く）ので、
これはフォントの持ち味であって補正してはいけないもの。

シートの仕様は3つだけ。

- 白地に黒でインクを書く（透過画素は地色扱い）
- 1枚 = Unicode の1ページ（256字）を 16x16 のマス目に並べる。
  左上がページの先頭、右下が末尾
- 1マスの寸法はファイル名に書く（`tenotext_8x11_cool.png` なら 8x11）

したがってシートの寸法は必ず「セル幅x16 × セル高x16」になる。
読み込み時にそこを検算していて、合わなければ落とす
（黙って字がずれるより、読めないと言われたほうが早い）。
インクが1画素も無い場合も落とす（白黒を逆に書いた事故を拾うため）。

**1フォントは複数ページを持てる。** ページ番号は符号位置の上位バイト（`cp >> 8`）。

| フォント | 収録ページ |
|---|---|
| 8x8 | `U+00xx` |
| 8x11 COOL | `U+00xx` `U+25xx` |
| 8x11 POP | `U+00xx` `U+25xx` |

`tenotext_8x11_25xx.png` は罫線素片・ブロック要素・幾何学模様のパックで、
COOL と POP が同じものを共有する（字の乗り方に癖が無い部分なので分ける必要がない）。
同じファイルを2回デコードしないよう、シートはパスで引けるようキャッシュしてある。

ページを持たない字は落とす。8x8 で罫線のプリセットを選んだ場合と、
CHARS にかな漢字を打った場合が主。黙って消えると「打ったのに出ない」に
なるので、GLYPH の情報行に `N dropped (has U+00xx)` と収録ページを出す。
全部落ちるとマッチャに当てる字が無くなるので、そのときは白紙を1つ立てて凌ぐ。

ギリシア文字・キリル文字はどのページにも無いので文字セットから外した。

`fonts/TenoText 8x8.otf` はまだ置いてあるが、これは **CSS の見出し用**で、
AA のパイプラインには関わっていない。

**パレットは動画全体で1組。** フレームごとに色を採ると、色そのものが毎コマ入れ替わって
激しくちらつく。全フレームから1組だけ採ることで色は動かなくなり、
副産物として GIF のグローバルカラーテーブルがそのまま使える。

**マッチングの誤差式をグリフについて展開してある。** ブロック q の再現色を
`bg + f_q·(fg-bg)` とおくと、誤差の総和は

```
Σ_q |bg + f_q·d - t_q|²  =  E + 2Σ_q f_q·a_q + |d|²·Σ_q f_q²
```

とペア側（E, a_q, |d|²）とグリフ側（Σf_q²）に分かれる。ペアごとに前者を1回求めれば、
グリフ1個あたりの計算は長さ Q の内積＋1乗算で済む。
GLYPHALT はグリフごとに RGB 3成分を回していたので、ここが約3倍の差になる。

**ペアのソートをやめた。** GLYPHALT はセルごとに 256 ペアを下界でソートしていた。
ここでは「下界が最小のペアだけ先に全グリフ評価して暫定最良を作り、残りは
下界が暫定最良を超えたら丸ごと飛ばす」順序にした。ソートが消えても
枝刈りの正しさは変わらないので、結果は全探索と一致する。

**TEMPORAL HOLD（ちらつき止め）。** 直前フレームと同じ組でも誤差がほとんど変わらないなら
そちらを据え置く。AA 動画は隣接フレームの微差で毎回別の字が選ばれてザワつくので、
これが入るかどうかで見え方がかなり変わる。既定 12%。
履歴を引き継ぐ必要があるので、Worker にはフレームを「連続した塊」で配っている。

**素材の切り出しは FPS / SPEED / START / LENGTH の4つ。**
以前は MAX FRAMES と VIDEO FPS の2つだったが、「何コマ拾うか」は結果ではなく
副産物なので、尺と速さで指定する形に変えた。コマ数の上限は 256 固定。

    出力コマ数 = min(256, round(LENGTH / SPEED × FPS))

FPS は代表的な 8/12/24/30/45/60 からの選択式にした。中間値を刻めても
「元動画と同じ 30」「軽い 12」を外す事故のほうが多い。
SPEED は 1.0〜4.0x（0.1刻み）で、尺を保ったままコマ数を減らす調整弁になる。

16s × 60fps は 960 コマになって 256 に当たる。黙って打ち切ると
「指定したのに尺が足りない」に化けるので、コントロールの下に
`→ 96 frames / 4.00s out @ 24fps` の見積りを出し、上限に当たったら赤にする。
見積りとデコードで式がずれないよう、計算は `Source.plan()` の1箇所だけに置いた。

**FPS は動画専用。** アニメ GIF/WebP は元のコマ間隔を持っているので、
そこへ FPS をかぶせて打ち直すと同じ絵が並ぶだけで太る（5fps の GIF を 24fps 化）。
アニメ画像は元のタイミングを保ったまま START/LENGTH で切り、
SPEED は表示時間の割り算だけで効かせる。窓の中が 256 を超えたぶんは
等間隔に間引き、飛ばしたコマの時間は残したコマへ足し込むので尺は狂わない。

**切り出し設定を変えたらデコードからやり直す。** どのコマを持ってくるかの話なので、
変換をやり直しても意味がない。File を `state.file` に持っておいて、
400ms のデバウンスで読み直す（動画のシークが遅いため）。
以前は読み込み時にしか設定を読んでおらず、後から FPS を動かしても効かなかった。

START/LENGTH のスライダーは素材の実尺に合わせて目盛りごと縮める。
ただし値をそのまま縮めると、2秒の GIF を1本挟んだだけで LENGTH が
2 のまま戻らなくなるので、ユーザーの希望値は `clipWant` に別途覚えておいて、
長い素材を読んだときに戻す。

**PREVIEW（1コマ確認モード、既定 ON）。** パレット・フォント・色調整の当たりを見るのに
毎回全コマ回すのは無駄なので、1コマだけ変換するモードを標準にした。
ここで大事なのは **パレットは PREVIEW 中も全フレームから採る** こと。
1コマ目だけで色を採ると、全コマ描画に切り替えた瞬間に色が変わって
確認した意味がなくなる。見えている絵は本番と同じものになる。
（1コマ目だけの色で採りたいときは SAMPLE FRAMES を 1 にすれば同じことができる）

フレームスライダーは PREVIEW 中だけ意味が変わり、「どのコマを確認するか」の指定になる。
動かすと1コマぶんだけ再変換が走る。TEMPORAL HOLD は前後のコマが要る仕組みなので
PREVIEW 中は効かない。PREVIEW のまま GIF ボタンを押した場合は、
1コマの GIF を出すのではなく PREVIEW を解除して全コマ描画してから書き出す。

**再描画のかかり方をモードで変えてある。**
PREVIEW 中は 1コマなので、いじった端から回す（リアルタイム）。
全コマ側では自動では回さず、CONVERT を押すまで待つ。
設定が結果に追いついていない間は CONVERT ボタンが赤くなる。
PREVIEW を外した時点でも自動描画はせず、CONVERT 待ちにしている
（外す操作＝レンダリング開始、にすると押し間違いが重い）。
GIF ボタンだけは例外で、追いついていなければ先に全コマ回してから書き出す。

**文字セットはテキストエリアが本体。** プリセットは「そこへ流し込む種」でしかなく、
選んだ瞬間には切り替わらない。ADD / OVERWRITE を押して初めて入るので、
手で足した字がプリセット選択で消えることがない（TEXTALT-V と同じ作法）。
ADD は既にある字を重複させず、空白だけは常に末尾へ寄せる。

**調整は Worker 側でかける。** BLUR と SOBEL は空間フィルタなのでフレーム全体を
なめる必要があるが、フレームが Worker に分かれているぶんコア数だけ並列に流れる。
16コマ 512x512 の実測で、BLUR + SOBEL を両方入れても全体で +54ms（856→910ms）。
彩度と色相はどちらも RGB の線形変換なので、2つの 3x3 行列を先に掛け合わせて
1本にしてから画素に適用している（HSV へ往復するより速く、結果は同じ）。

**SOURCE ボタン。** 同じ寸法・同じ調整をかけた変換前の画素を同じキャンバスに出す。
ここに映るのはマッチャが実際に見ている画素そのものなので、
「AA が悪いのか、その手前の調整が悪いのか」を切り分けられる。

**GIF エンコーダは自前。** 出力が最初から16色以下のパレット画像なので、
減色もディザリングも要らず、LZW とヘッダ組み立てだけで済む。
量子化を挟まないぶん、画面の見た目と完全に一致する GIF が出る
（ブラウザのデコーダで読み直して画素単位で一致することを確認済み）。
DIFF ENCODE は変化した画素の外接矩形だけを書き、矩形内の未変化画素を透明にする。
全画面が動くコマでは逆に太るので、両方詰めて小さいほうを採っている。

**ASCII モード（背景オミット）は探索も軽くなる。** 背景を PAPER に固定すると
(bg, fg) の候補が nC² から nC に落ちる。16色なら 256通り → 16通り。
実測で全コマ描画が 994ms → 419ms（2.4倍速）。
ただし背景が固定されると、明るいベタ面を出すには塗り率 1.0 のグリフが要る。
`U+00xx` ページだけだと一番濃い字が `M` の 0.58（8x8）/ 0.55（COOL）/ 0.51（POP）
どまりで、ASCII モードの明部が伸び切らなかった。

`U+25xx` ページでこれが解決した。ブロック要素は塗り率が設計どおりに並ぶ。

| 字 | 塗り率 |
|---|---|
| （空白） | 0.000 |
| `░` U+2591 | 0.250 |
| `▒` U+2592 | 0.318 |
| `▓` U+2593 | 0.511 |
| `█` U+2588 | **1.000** |

8分割ブロック（`▁▂▃▄▅▆▇█` / `▏▎▍▌▋▊▉█`）を足すと、その間もほぼ等間隔に埋まる。
実測では ASCII モードで SHADE RAMP を使うと、白いベタ面がそのまま白く出る。

**CELL GAP はアートの画素で数える。** SCALE 4x なら隙間も 4px になる。
隙間はセル座標の上で足してから拡大しているので、拡大率に対して一定に見える。
外周にも入れて額縁状にしている（右下だけだと左上端が詰まって不揃いになる）。
隙間を入れるとセルの実効的な縦横比が変わるので、行数計算には
`(cellW+gap)/(cellH+gap)` を渡している。素の比のままだと 8x11 で約3%、
4x6 で約7% アスペクトが狂う。実測では gap 0/1/2 のいずれも誤差1%以内。

**PAPER は ASCII モードの背景と CELL GAP の色を兼ねる。**
黒・白・パレットから選択。パレットに無い色を選んだときは1色足す
（GIF のカラーテーブルは2のべき乗に切り上がるので容量の問題は出ない）。

**パレットは AUTO / FILE の2モード。** FILE では PNG を自然サイズのまま走査して
出てきた順に色を拾い、重複を落として16色で打ち切る。
GLYPHALT は必ず 16x1 へ縮小していたため、8x1 の Greenscale だけ補間で
引き伸ばされて8色が16色の中間色に化けていた。ここではその通りに 8色として読む。
同梱パレットの実際の色数は Glay 13色・MSX 15色・Greenscale 8色で、残りは16色。

**書き出しの拡大は整数倍のみ。** SCALE は 1x / 2x / 3x / 4x。
GIF はパレット番号の配列の段階で画素を複製するので、拡大しても補間は一切かからない
（画像を引き伸ばすのではなく、最初から大きいラスタを組んでいる）。
PNG も `imageSmoothingEnabled = false` で同じ扱い。

**書き出し量の警告。** 面積は倍率の二乗で効くので、4x は 16倍になる。
全コマぶんの総画素数を SCALE の横に出し、しきい値を超えたら赤字にして
一度だけ確認を挟む。止めはしない。

## 表記について

UI・ドキュメント上の名前は `ANIMALT-Δ`。
ディレクトリ名と書き出しファイル名（`animalt_YYYYMMDD_hhmmss.gif`）は
半角英数のみのルールに従って `Animalt` / `animalt` のままにしてある。
Δ は TenoText 8x8 に収録されているので、見出しフォントでそのまま出る。

## 動作環境

- アニメーション GIF / WebP のデコードに WebCodecs の `ImageDecoder` を使う。
  非対応ブラウザでは1コマ目だけの静止画として扱い、その旨を status に出す。
  自前の GIF デコーダを書けば外せる依存。
- 動画は `<video>` をシークしながら拾う。切り出しは FPS / SPEED / START / LENGTH で決め、
  コマ数は 256 で頭打ちにする。尺が読めない・シークが返ってこない素材は
  待ち続けずにエラーにする（8秒でタイムアウト）。

## サイトへの組み込みで足したもの

- `<head>` に title / description / OGP 一式・`/main.css`・`/menu.js`
- フォント参照をサイト共通の `/fonts/` へ（ツール内の重複コピーは削除）。
  ただし `fonts/tenotext_*.png` は AA のグリフ素材なのでツール内に残す
- 自前の見出しを `header` から `.app-header` へ。
  サイト共通の上部ナビ（`#sodenmir-topbar`）も `<header>` なので、
  素の要素選択子だとそちらまで巻き込む
- モバイルナビを被せる指定。このページだけ `body` が 100vh の全画面レイアウトで、
  ナビが通常フローのままだと開いた瞬間に作業領域を潰す（`overflow: hidden` なので
  押し出された分は見えない）。上部ナビの実測高を CSS 変数に流して真下に置いている
